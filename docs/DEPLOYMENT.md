# Развёртывание LibraryBot

Код подготовлен для одного процесса бота и PostgreSQL 18. Сервер в этой задаче не выбран; команды ниже предназначены для его последующего запуска. Используется polling, поэтому домен, HTTPS и входящий webhook не требуются.

## Настройки сервера

Скопируйте `.env.example` в `.env` и задайте `BOT_TOKEN`, `POSTGRES_PASSWORD`, при необходимости `BOT_TIMEZONE`. Пароль PostgreSQL для предоставленной Compose-конфигурации должен состоять из случайных латинских букв и цифр: он включается в URL подключения. Можно получить его командой `openssl rand -hex 24`. Файл `.env` должен быть доступен только владельцу (`chmod 600 .env`).

В Compose `DATABASE_URL` формируется для внутреннего сервиса `db`; значение из примера `.env` предназначено для прямого Python-запуска с собственной базой. Не публикуйте `5432` в интернет. Health-порт `10000` привязан к localhost сервера.

Остановите локальный бот с тем же токеном, затем выполните:

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=60 bot
curl --fail http://127.0.0.1:10000/health
```

Ответ `{"service":"LibraryBot","ready":true}` означает, что приложение и polling запущены, база отвечает и планировщик недавно завершил подготовку расписаний. `503` означает, что готовность пока не подтверждена. Ложного ответа «бот работает» от отдельного пустого веб-сервера нет.

В PostgreSQL 18 используется том `/var/lib/postgresql`; данные находятся внутри него в каталоге версии. См. [официальный образ PostgreSQL](https://hub.docker.com/_/postgres) и [руководство Docker](https://docs.docker.com/guides/postgresql/). Обновление PostgreSQL на следующую основную версию требует отдельного переноса базы; замены номера образа недостаточно.

## Перенос локальных данных

Можно начать сервер с пустой базой, восстановить личный экспорт через меню бота или перенести весь локальный кластер через дамп. Для последнего остановите только процесс локального бота; PostgreSQL оставьте работающим на время выгрузки. Из PowerShell запускайте этот код из корня репозитория:

```powershell
@'
import os, subprocess
from pathlib import Path
from dotenv import dotenv_values
from psycopg.conninfo import conninfo_to_dict
info = conninfo_to_dict(dotenv_values('.local/db.env')['DATABASE_URL'])
env = {**os.environ, 'PGPASSWORD': info['password']}
Path('backups').mkdir(exist_ok=True)
subprocess.run([r'C:\Program Files\PostgreSQL\18\bin\pg_dump.exe',
    '-h', info['host'], '-p', info['port'], '-U', info['user'], '-d', info['dbname'],
    '-Fc', '-f', 'backups/local-transfer.dump'], env=env, check=True)
'@ | .venv/Scripts/python.exe -
```

Передайте дамп на сервер приватным способом. Запустите там `docker compose up -d db`, дождитесь готовности и выполните `sh scripts/restore.sh backups/local-transfer.dump`. Дамп содержит профили, книги и служебные записи; не добавляйте его в репозиторий.

## Резервные копии и обновления

`sh scripts/backup.sh` создаёт дамп PostgreSQL в формате custom с правами владельца. Храните копии также вне сервера. Частоту и срок хранения определяет владелец сервера; автоматическое удаление копий не настроено.

Перед обновлением сделайте резервную копию, получите код и пересоберите контейнер:

```sh
sh scripts/backup.sh
git pull --ff-only
docker compose up -d --build bot
curl --fail http://127.0.0.1:10000/health
```

Миграции выполняются под PostgreSQL advisory lock. Единственный экземпляр бота удерживает отдельную блокировку; второй процесс с той же базой завершится с понятной ошибкой. Это не предотвращает конфликт двух процессов с одним токеном и разными базами — локальный экземпляр нужно остановить перед запуском сервера.

Не используйте `docker compose down -v` для обычного обновления: эта команда удаляет том базы. Для остановки достаточно `docker compose stop`.

## Группы и уведомления

Участники начинают диалог в ЛС. После добавления бота в группу выдайте ему права администратора и отправьте `/start`. Приглашения получают известные профили, чьё участие подтверждено; остальные используют кнопку перехода в ЛС. Только согласие подключает профиль. В группе галочки не засчитываются и личные цитаты не отправляются.

Восстановление после перезапуска обрабатывает пропущенные местные дни по порядку. Старые цитаты и напоминания не рассылаются пачкой: допустимое опоздание уже поставленной в очередь отправки — пять минут. Пропущенные расписания без очереди не воспроизводятся.

Журнал `deliveries` сохраняет результаты `sent`, `failed`, `cancelled`, `uncertain`. Telegram Bot API не поддерживает ключ идемпотентности для отправки: после неоднозначного сетевого таймаута бот не повторяет сообщение автоматически. Это исключает повторную рассылку, но такое уведомление может остаться недоставленным. Пользовательский прогресс и операции монет от доставки уведомлений не зависят.
