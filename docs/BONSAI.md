# Процедурный бонсай

Новые главные деревья используют `magic-bonsai-v1`: полный рисунок на 365 частей создаётся один раз при создании профиля или после гибели незолотого дерева. Каждая отметка и удобрение открывают следующую часть. Деревья новых книг имеют 100 частей; их прогресс — целая доля прочитанного `page * 100 // total`. Отметка книги может открывать несколько частей согласно дневной норме, но все промежуточные состояния определены. Исправление страницы владельцем меняет показанный префикс, не выдавая дней или монет.

## API и данные

```python
from bot.bonsai import Tree, generate_tree, render_tree, validate_tree

tree = generate_tree(max_parts=100, seed="reader:first-tree")
validate_tree(tree)
saved = tree.to_dict()  # JSON: seed, algorithm_version, поле, основание и все parts
restored = Tree.from_dict(saved)
for k in (1, 10, 25, 50, 75, 100):
    drawing = render_tree(restored, current_parts=k)
```

`seed` допускает целое число или строку. Без него создаётся случайный ключ, возвращаемый в `Tree`. Один seed, размер и версия дают одинаковую геометрию. Полная последовательность сохраняется в JSONB `tree_plan`, поэтому открытие меню и рост не запускают генерацию повторно. У главного дерева раскрытый префикс хранится в `tree`, его длина — текущий прогресс; у книги прогресс определяется страницами. Экспорт версии 2 включает полные планы и состояние роста.

Поддерживаются размеры от 1 до 600 частей. Некорректный размер или превышение ограничения вызывают понятную ошибку, без уменьшения числа частей. Сетка адаптивная: ширина до 28 клеток, высота до 64 строк; рисунок ограничен 2700 единицами UTF-16, чтобы осталось место для карточки. Главная цель бота остаётся 365.

## Генерация и отрисовка

Сначала отдельный RNG от хеша seed, версии и номера попытки выбирает профиль (`windswept`, `classic_bonsai`, `rounded`), наклон и изгиб. Связный ствол растёт от основания, затем асимметричные боковые ветви. Их концы задают центры округлых облаков листвы. Следующие листья выбираются только из ортогонального фронтира, с весами близости к облакам, компактности и распределения между ярусами. Небольшие окна сохраняют просветы у ветвей. Неподходящие формы отбрасываются до выдачи дерева; после успешной генерации части не переставляются и не сглаживаются.

Около 2–4% частей больших деревьев заменяются магическими акцентами, максимум 6%. Они появляются после 60% роста, не занимают ствол и разделены минимум тремя клетками по одной из осей. Все символы окончательны ещё до первой отрисовки. Деревья меньше 30 частей обходятся без магии.

Рендер всегда создаёт полное поле, заполняет пустоты одинаковыми идеографическими пробелами U+3000 и показывает `parts[:k]`. Ширина, высота, координаты, пробелы и уже раскрытые эмодзи остаются неизменными. При `k=0` поле пустое; при `k+1` меняется ровно одна клетка. Заголовки и числа роста находятся вне HTML `<pre>`.

## Telegram

Пример интеграции; объект дерева сохраняют до отправки и повторно используют при росте:

```python
from html import escape

def text(tree, k):
    return f"🌙 Бонсай · {k}/{tree.max_parts}\n<pre>{escape(render_tree(tree, k))}</pre>"

message = await bot.send_message(chat_id, text(tree, 1), parse_mode="HTML")
await message.edit_text(text(tree, 2), parse_mode="HTML")
```

Растущие бонсаи показываются текстом в ЛС и группе. Подпись фотографии ограничена 1024 символами и не вмещает большой рисунок; поэтому групповые меню теперь текстовые и редактируют одно сообщение через `editMessageText`. Старое меню с фотографией при первом переходе заменяется один раз, поскольку Telegram не умеет превращать photo в text. На 365 частях сохраняется прежняя постоянная золотая награда в виде PNG; переход между текстом и наградой также заменяет сообщение.

Эмодзи и U+3000 могут иметь разную визуальную ширину в клиентах Telegram: моноширинный режим не даёт универсальной гарантии. Формальные проверки контролируют клетки, UTF-16 и отсутствие внутренних переносов в строках данных. Приёмку визуального выравнивания в Telegram Desktop, Android и iPhone нужно проводить отдельно; она не заменяется SVG-галереей.

## Совместимость и проверка

Миграция 003 помечает существующие планы как `null`: они остаются на прежнем ASCII-алгоритме и сохраняют свои рисунки. Книги прежней версии не перерисовываются. После гибели прежнего главного дерева начинается новый бонсай. Экспорты версии 1 принимаются с тем же правилом совместимости; повторный экспорт использует версию 2. Импорт проверяет полные планы, последовательность, символы, границы, связность и совпадение раскрытого префикса, прежде чем менять профиль.

Для галереи из 20 деревьев на 100 частей и примеров последовательного роста:

```sh
python -m scripts.preview_bonsai
```

Получаются `.local/bonsai-preview/gallery.html`, два SVG-листа и JSON примеров. Это синтетические данные; они не содержат профилей пользователей. SVG служит проверке силуэтов, HTML — ручному просмотру настоящих эмодзи. Автотесты проверяют все префиксы для размеров 1, 5, 20, 30, 50, 100, 200, 365 и 600, три seed каждого размера, двадцать разных силуэтов, повреждённый JSON, перезапуск, импорт, гибель и старые рисунки.

## Временный локальный просмотр

По запросу владельца можно на один час включить отдельное тестовое дерево на 365 частей через `PreviewStore.enable(owner_id, now)`. Сессия находится только в игнорируемом `.local/tree_preview.json`: без этого файла режим выключен, в Docker-образ он не попадает. Включить или продлить сессию через Telegram нельзя.

Для указанного владельца в ЛС каждая ✅ открывает одну часть тестового дерева. Кнопки «+10» и «До конца» ускоряют просмотр; «Завершить просмотр» возвращает обычные отметки. Полный план и текущий префикс сохраняются между перезапусками, срок не продлевается. По истечении часа обычные ✅ снова обрабатываются как чтение с дневным ограничением; устаревшие кнопки просмотра показывают сообщение об истечении срока. Тестовое дерево не меняет книги, страницы, отметки, серию, монеты или золотую награду. Режим недоступен другим владельцам и группам.

## Настройка следующей версии

В `_build` задаются масштаб поля, длина и толщина ствола, изгиб, число и длина ветвей, радиусы облаков и сила весов фронтира. Количество магии задаётся долей при выборе поздних листьев; абсолютная граница 6% и расстояния проверяются валидатором. После настройки снова проверяются точное число частей, все префиксы и визуальная галерея. Изменения геометрии выпускают под новым `algorithm_version`; сохранённые полные планы прежней версии продолжают рендериться без новой генерации.
